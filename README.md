# eat-sar

Code for the IEEE Geoscience and Remote Sensing Letters (GRSL) letter

**"Environment-Conditioned Score Thresholding for Clutter-Invariant
False-Alarm Operation of Deep SAR Ship Detectors"**
(S. Hu, L. Chen, Q. Zhang, and W. Liu).

Deep SAR ship detectors are deployed with one global confidence threshold.
Because sea clutter shifts the post-NMS score distribution from scene to
scene, the false-alarm rate delivered by a fixed threshold drifts with
clutter: at the production threshold T = 0.40, the high-clutter tertile of
both benchmarks receives 5.2–6.3× the false alarms per image of the
low-clutter tertile. This repository implements a training-free policy
`T(e)` that conditions the post-NMS score gate on a per-image clutter
proxy `e` — the standard deviation of background grey levels outside the
detector's own boxes — and calibrates it offline, per clutter stratum, to a
false-alarm budget or a precision target. At matched targets this reduces
the cross-stratum spread of false alarms per image by 2.8–41× across twelve
pre-specified settings (bootstrap 95 % intervals excluding zero), which
neither a global threshold fitted to the same target nor a random-binning
placebo achieves.

The letter also reports, honestly, what the method does *not* do: on
well-trained detectors its F1-balanced variant gains no more aggregate F1
than a validation-tuned global threshold. The full control battery
(validation-optimal global threshold, random-binning placebo,
matched-operating-point control, test-fit oracle, 10-fold
cross-validation, dilation sweep, cross-sensor transfer) is part of this
repository.

## Datasets

The datasets themselves are **not** redistributed here; download them
from their official sources and point the conversion script at them:

- **SARDet-100K** — official repository and download instructions:
  <https://github.com/zcablii/SARDet_100K>
- **SAR-Ship-Dataset** — official repository and download instructions:
  <https://github.com/CAESAR-Radi/SAR-Ship-Dataset>

```bash
# converts both datasets into a common layout (8-bit grey-level tiles + YOLO labels)
python scripts/10_revision/convert_datasets.py \
    --sarship-root /path/to/SAR-Ship-Dataset \
    --sardet-root  /path/to/SARDet-100K \
    --out-root     work/yolo
```

We use the ship-containing subsets: SARDet-100K official val/test
(6441 / 6496 images) and a deterministic 80/10/10 split of
SAR-Ship-Dataset (calibration 4381, test 4381). The SAR-Ship-Dataset test
split is reproduced exactly by `make_sarship_test_split.py` and recorded in
`manifests/`.

## Quickstart (one command per stage)

Windows (`scripts/10_revision/run_revision.cmd`; edit the path variables
in the first lines to your machine — see
`scripts/10_revision/RUN_REVISION_WINDOWS.md`):

```bat
run_revision.cmd convert      % datasets -> common layout
run_revision.cmd cache-ship   % cache SAR-Ship-Dataset predictions
run_revision.cmd cache-sardet
run_revision.cmd analyze      % main eval + controls + CV + k-sweep + transfer
run_revision.cmd cfar         % false-alarm stability eval (Table I, Fig. 2)
run_revision.cmd figures      % figure data exports
```

Linux/macOS: the same Python scripts are called directly; see
`scripts/10_revision/RUN_REVISION.md` (AutoDL variant) for the command
lines, or read `run_revision.cmd` — each line is a plain `python` call.

Detector training (only needed if you do not use the released weights) —
`configs/default.yaml` sets YOLOv8s, 100 epochs, seed 42, single class:

```bash
python scripts/03_train/train_yolov8.py --data configs/yolo/sarship.yaml --name sarship_yolov8s
# or reproduce both models in one go (adjust paths first):
bash scripts/03_train/retrain_both.sh
```

## Per-image proxy values

`manifests/{sardet,sarship}_{val,test}_e.csv` contain the label-free
clutter proxy `e` (and the k-sweep variants) for every image of the four
splits, plus the fitted tertile bin. They are generated from the full
manifests by:

```bash
python scripts/10_revision/make_public_manifests.py \
    --manifest work/cache_preds/sarship_test/manifest_proxy.csv \
    --dataset sarship --split test --out-dir manifests
```

No ground-truth information is required to compute `e` (the paper reports
that the detector-box version agrees with a GT-masked version to
Spearman ρ ≥ 0.99).

## Weights

The two retrained YOLOv8s checkpoints are distributed as GitHub release
assets (see `weights/README.md` for URLs and SHA-256 checksums). The
`best.pt` files are the exact models behind every number in the letter.

## Environment

Python ≥ 3.9, PyTorch, Ultralytics YOLOv8, pandas, numpy, scipy,
matplotlib. Training used a single GPU; all evaluation stages run on CPU
overnight or a single GPU in minutes. Exact versions used for the letter
are listed in `requirements.txt`.
